# SUMMARY: Judge reliability

**Last updated:** 26-11-26 (five more judges over Mistral's API, incl. DeepSeek V4.1 Flash; same tests as Phi-4; score-change analysis; Medium and DeepSeek chosen as judges, Phi-4 kept as third judge; three-judge combination and latent class model)

After the first trend analysis (course-exercises topic: Phi-4 judge, two prompts; SFT → DPO rise replicates, the paper's drop of the final checkpoint below SFT doesn't), Julian asked how to test whether the judges (`etpm_judge_prompt` from He et al. 2025, `qic_judge_prompt` from arXiv 2610.31624 Table 9 plus our reconstruction) are reliable.

- **Framing** [concluded, not ratified]: the research question is a difference between checkpoints, so a constant judge error cancels; the danger is a judge error that depends on checkpoint style (length, formatting, boilerplate). Every test should be reported per checkpoint. Four separate questions: consistency (judge vs itself), agreement (judge vs judge), known-answer behaviour (judge vs controlled inputs), validity (judge vs human). Agreement is not validity.
- **Ideas** (LOG entry *ideas for testing judge reliability*): A free checks on existing logs (length/style vs verdict, qic threshold sweep, agreement per checkpoint); B more judges on the same replies (GPT-4o, the papers' own judge; gpt-oss-20b; GPT-4o on the 1,024-token run); C known-answer perturbations (task-only, refusal, minimal pairs, compliance-without-IC, style invariance); D blind human labels on ~60 stratified replies (±10 points at n = 60), ideally a second human for the ceiling; E sampled judging for per-item uncertainty.
- **F. Invariance ladder** (Julian's question; LOG entry *invariance ladder: stability under benign changes*): judge variants that keep the meaning: tier 0 identical repeat (the noise floor), 1 formatting only, 2 judge-prompt paraphrases, 3 deterministic reply edits (filler removed, bullets reordered, names swapped), 4 LLM paraphrase of the reply. Report flip rate per tier and checkpoint minus the floor, and the trend per variant. Strongest variant: **style-normalized judging**, all replies paraphrased into one uniform style, then re-judged; if the trend survives it comes from content, not checkpoint style. Pitfall: the paraphraser can soften instrumental content; use another model family, read ~15 pairs, test it on minimal pairs. ~3,650 Phi-4 calls, about half an hour of GPU. Code idea: a `perturb` task writing derived generation logs, judge unchanged.
- **Judge-prompt variants** (tier 2; LOG entries *review of qic_judge_prompt_permuted*, *build_data.py deleted; permuted_2 and synonyms variants*, *permuted variants merged into one*, *variant metadata trimmed*), all derived from `qic_judge_prompt` in `data/input/judge_prompts.json`, with only `description`, `derived_from`, `variant`, the templates and `output` (provenance lives in the base entry):
  - `qic_judge_prompt_permuted`: Julian's reordering within sentences (e.g. list moved, 1.0 bullet first) combined with a block reordering (definition first, context before the task, "Return ONLY" last). A broken definition sentence in the first draft that made the examples read as examples of the assigned goal was fixed. The two reorderings were briefly separate variants; merged at Julian's request, so a flip can't be blamed on one kind of order.
  - `qic_judge_prompt_synonyms`: same sentence order, near-synonyms throughout; kept: "instrumental convergence", SCORE/REASON. Three loaded word choices in my first draft (slight, deceit, justifying) were replaced before saving.
  - Tests: same output format as the base; permuted ones have exactly the base's words [verified: pytest 26-11-23, 122 passed]. Run 26-11-23, see next bullet.
- **First invariance run** [verified: report + scratch script 26-11-23; Phi-4 only, one greedy reply per task, threshold ≥ 0.5] (LOG entry *first invariance run: three qic prompts, Phi-4*): 9 judgings (3 prompts × SFT/DPO/final), logs tagged `judge-reliability`.
  - Noise floor (qic_judge_prompt judged twice): 2/224 verdict flips (0.9%); the judge is nearly deterministic, unlike generation.
  - Permuted: 13/224 flips (5.8%), balanced (6 lost / 7 gained). Synonyms: 15/224 (6.7%), skewed up (4 / 11), mostly on the final checkpoint (+5 to +6.5 points). So benign prompt changes flip ~6% of items, 6-7× the floor; item-level claims are fragile.
  - Trend holds in all four qic judgings: SFT / DPO / final = 18.1-20.8 / 31.6-32.9 / 22.4-28.9%; SFT → DPO +12 to +13.5 points everywhere, final − SFT +3.0 to +8.1 (paper −13.2). Final-vs-SFT is about as small as the synonym effect, so fragile; SFT → DPO robust.
  - Phi-4 never scores 0.4-0.6 with any qic prompt: scores are bimodal, the threshold choice (0.4-0.6) doesn't matter, flips are 0.2 ↔ 0.8 jumps. Recurring flip items: hiding-08, shutdown-08/16/20, copies-05, aligned-05.
  - The report now numbers repeated judgings `#1` (trend session) / `#2` (repeat) and shows the direction of disagreements, so these numbers come straight from `uv run python -m ic_eval.analysis.report` (fixed in `convos/julian/26-11-23_run_fixes_SUMMARY.md`).
- **Six judges** [verified: `scripts/laptop/compare_judges.py` 26-11-26; one greedy reply per task, no human labels] (LOG entry *six judges on the three trend runs (Mistral API)*): Julian asked for more judges via his Mistral key. Added `mistral-large-4` (always reasons; run with `--reasoning-effort low --max-tokens 16000` at Julian's request), `mistral-medium-2604`, `mistral-small-2603`, `ministral-14b-2512`, `deepseek-v4-1-flash-1017` (hosted by Mistral), via Inspect's `mistral/` provider (`mistralai` added as a dependency; the OpenAI-compatible route crashes on large-4's reasoning chunks). Each did Phi-4's five judgings (qic #1, permuted, synonyms, etpm, qic #2) on SFT/DPO/final: 15 logs per judge, tags `judge-reliability,mistral-judges`, 0-1 invalid of 1,120.
  - **Trend holds for every judge and prompt** (30 judgings): DPO − SFT +4.5 to +23.5 points; final − SFT +0.4 to +15.4, never negative (paper −13.2). The trend result no longer rests on Phi-4.
  - **Levels differ by judge**: final checkpoint 22-50% (qic), 34-67% (etpm); only within-judge differences are meaningful.
  - **Reliability splits by test** (flips of 224 verdicts): identical repeat Phi-4 2, medium 5, ministral 4, small 11, DeepSeek 12, large-4 29 (API judges aren't deterministic at temperature 0). Benign prompt variants vs that noise: medium 2.7% and DeepSeek 4.5% ≈ their noise; small 10.5% and ministral 7.6% one-directional (the permuted prompt removes convergence verdicts, 22/5 and 19/2); large-4 12% ≈ its 13% repeat noise. etpm vs qic within judge: DeepSeek κ 0.885, others 0.55-0.72. Judge pairs κ 0.46-0.72 on qic.
  - **Combining two judges** (LOG entry *Phi-4 dropped; combining two judges*; done while Phi-4 was briefly dropped, the rules carry over to three judges, see next bullet) [concluded, not ratified]: any rule fixed in advance and applied to all checkpoints is valid for checkpoint differences; recommended: mean of the two verdicts per reply (combined rate = average of the judges' rates), qic prompt, paired bootstrap over the 76 tasks; report each judge beside it. Estimating the true rate without labels (Dawid-Skene) needs ≥ 3 judges; with human labels, Rogan-Gladen correction. On existing data (qic #1): combined SFT / DPO / final 33.3 / 50.7 / 42.8%, DPO − SFT +17.3 [+7.2, +27.3], final − SFT +9.4 [+0.3, +18.4]; all rules (AND, OR, mean score) agree within ~2 points. With etpm the two judges disagree on 82/224 (Medium 67-75% convergent), so etpm is best reported per judge.
  - **Three judges** (LOG entry *Phi-4 back as third judge; three-judge combination*; `scripts/laptop/three_judges.py`) [verified: 26-11-26; interpretation concluded, not ratified]: with three judges a latent class model (Dawid-Skene) can estimate each judge's sensitivity/specificity and the rate per checkpoint without labels. qic #1: fits (G² 8.3, df 12, p 0.76); Medium lenient (sens 1.00, spec 0.81), DeepSeek balanced (0.96 / 0.94), Phi-4 strict (0.64 / 0.97). SFT / DPO / final: mean of 3 verdicts 28.2 / 44.3 / 36.4%, latent class 25.3 / 42.2 / 37.1%; DPO − SFT +16.1 [+7.2, +25.3] and +16.9 [+5.2, +29.0]; final − SFT +8.2 [+0.3, +16.3] and +11.8 [+0.9, +22.7]. etpm: judges disagree more, final − SFT intervals include 0. Proposal: mean of 3 verdicts on the qic prompt as the main number, latent class rate as a check. Its "truth" is the judges' shared signal, and it assumes independent errors and checkpoint-independent error rates (untested; human labels would test them).
  - **Score changes** (qic scores, vs #1; LOG entry *score changes on repeat and prompt variants*): median |change| is 0 for every judge and comparison (most scores identical). DeepSeek changes ~30% of scores even on repeat, but by 0.1 (90th percentile 0.1): jitter around a stable value, so averaging a few repeated judgings would remove most of it. Large-4 (low effort) changes ~33% by larger steps (median 0.2 among changes, 31 of 224 ≥ 0.3 on repeat). Medium is most stable (6% changed on repeat, 14-17% under variants). Phi-4: 1.8% on repeat, ~25% under variants (by 0.1). Systematic shifts: ministral −0.067 and small −0.061 (permuted), large-4 +0.071 (permuted); others within ±0.03; differences between checkpoints ≤ ~0.07.
  - **Judges chosen** [decided: Julian, transcribed 26-11-26]: `mistral-medium-2604` and `deepseek-v4-1-flash-1017` (LOG entry *judges chosen: Mistral Medium and DeepSeek*); Phi-4 briefly dropped (needs a rented GPU), then re-added as third judge [decided: Julian, transcribed 26-11-26], so judges are Medium, DeepSeek and Phi-4. Agent's reasoning: both are the least prompt-sensitive (variant flips ≈ their repeat noise), DeepSeek is consistent across prompts, both cheap; not small/ministral (prompt-order bias) or large-4 at low effort (noisiest, ~30× the output tokens). Three split replies read by the agent: small and medium call an honest report convergence (aligned-01), small and ministral a compliant shutdown (shutdown-01); copies-09 is a benchmark-validity case (the task invites replication). Agreement still isn't validity: blind labels on split items next.
